# 07 — Design System

> A timeless visual language for an engineering knowledge base.

---

# Purpose

The Design System establishes the visual language, interaction principles, and design philosophy that govern the entire portfolio.

It is not merely a collection of colors, fonts, or UI components.

It is a framework for communicating engineering thinking through interface design.

Every visual decision should reinforce the brand identity:

> Calm.
> Intentional.
> Structured.
> Technical.
> Human.

The interface should disappear behind the content while quietly communicating craftsmanship.

---

# Design Philosophy

The portfolio should feel less like a personal website and more like an engineer's workspace.

The experience should resemble walking into a carefully organized engineering desk:

- documentation neatly arranged
- diagrams pinned together
- architecture sketches nearby
- source code within reach
- notes connected by ideas rather than chronology

The design exists to support thinking.

Not entertainment.

Not marketing.

Not trends.

---

# Core Principles

## 1. Content First

Content is the product.

Layouts should always prioritize readability over decoration.

Users should immediately begin reading rather than trying to understand the interface.

Every visual element must justify its existence.

---

## 2. Engineering Precision

Spacing should be mathematically consistent.

Typography should establish clear hierarchy.

Layouts should communicate structure before aesthetics.

The UI should feel engineered rather than artistically composed.

---

## 3. Calm Interfaces

Avoid visual noise.

No unnecessary gradients.

No heavy shadows.

No excessive animations.

No decorative illustrations competing with content.

The interface should reduce cognitive load.

---

## 4. Timelessness

Design trends change.

Engineering principles remain.

Avoid styles strongly associated with a specific era.

Prefer simple typography, balanced spacing, and restrained color palettes.

The website should still feel modern five years from now.

---

## 5. Information Density Without Clutter

Engineers consume large amounts of information.

Provide generous spacing while allowing meaningful content to remain visible.

The interface should encourage exploration without overwhelming users.

---

## 6. Documentation Over Marketing

The goal is understanding.

Not conversion.

Not sales.

Not persuasion.

Pages should explain ideas rather than advertise expertise.

Trust should emerge naturally from the quality of the work.

---

# Brand Metaphor

## Engineering Desk

Everything should reinforce the feeling of an organized engineering workspace.

Visual references include:

- notebooks
- technical documentation
- architecture diagrams
- whiteboards
- terminal windows
- code editors
- specification documents

Avoid visual references associated with agencies, startups, or marketing portfolios.

---

# Visual Personality

The interface should feel:

- Quiet
- Intelligent
- Curious
- Reliable
- Intentional
- Methodical
- Technical
- Modern
- Minimal
- Approachable

It should never feel:

- Loud
- Flashy
- Over-designed
- Corporate
- Playful
- Trendy
- Chaotic

---

# Design Influences

The design language draws inspiration from products known for clarity and craftsmanship rather than imitation.

Influences include:

- Linear
- Vercel
- GitHub
- Stripe Documentation
- Raycast
- Apple Developer Documentation
- Notion (documentation hierarchy only)

Each contributes principles rather than visual styles.

---

# Color Philosophy

Color communicates meaning.

Not decoration.

Most of the interface should remain neutral.

Accent colors should appear only when highlighting important information.

Examples:

- active navigation
- links
- success
- warnings
- security callouts
- diagrams

Whitespace should remain the dominant visual element.

---

# Typography Philosophy

Typography is the primary design element.

Hierarchy should be established through:

- size
- weight
- spacing
- rhythm

—not through excessive color or decoration.

Readable documentation is more important than stylistic expression.

---

# Layout Philosophy

Layouts should feel architectural.

Pages should have:

- predictable spacing
- consistent rhythm
- clear sections
- strong alignment

Every page should communicate structure before content.

---

# Iconography

Icons should support comprehension.

Never decoration.

Prefer simple outline icons.

Icons should appear primarily for:

- navigation
- metadata
- content classification
- status

Avoid oversized hero illustrations.

---

# Motion Principles

Motion should explain.

Never distract.

Animations should:

- communicate hierarchy
- indicate state changes
- reinforce navigation
- improve orientation

Avoid:

- bouncing
- spinning
- dramatic transitions
- attention-seeking effects

Motion should feel almost invisible.

---

# Code Presentation

Code is first-class content.

Code blocks should prioritize readability.

Requirements:

- syntax highlighting
- copy button
- filename labels where appropriate
- line highlighting
- consistent spacing
- readable typography

Large code examples should remain comfortable to read.

---

# Diagrams

Architecture diagrams are central to the brand.

Use consistent visual language for:

- system architecture
- sequence diagrams
- data flow
- deployment architecture
- security models

Prefer clarity over artistic complexity.

---

# Imagery

Photography should be minimal.

Use images only when they improve understanding.

Examples:

- architecture sketches
- diagrams
- screenshots
- dashboards
- terminal output

Avoid stock photography.

---

# Components Should Feel

Every component should communicate:

Reliability.

Examples:

Buttons should feel deliberate.

Cards should feel organized.

Navigation should feel predictable.

Tables should feel documentation-focused.

Code blocks should feel developer-friendly.

Search should feel instant.

---

# Accessibility

Accessibility is a design requirement.

Not an enhancement.

Every interaction should consider:

- keyboard navigation
- screen readers
- color contrast
- focus visibility
- semantic HTML
- reduced motion preferences

Engineering excellence includes accessibility.

---

# Visual Consistency

Every page should answer "yes" to these questions:

✓ Is the content immediately readable?

✓ Does spacing feel consistent?

✓ Is hierarchy obvious?

✓ Does every component have a purpose?

✓ Is motion restrained?

✓ Does the interface disappear behind the content?

---

# Design North Star

If a design decision is uncertain, choose the option that better supports learning.

This website exists to help engineers understand ideas.

Everything else is secondary.
